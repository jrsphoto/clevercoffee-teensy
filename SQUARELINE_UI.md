# SquareLine UI — how the panel's screens are authored

The display head's screens are being moved into **SquareLine Studio** so John
can adjust layouts himself. This file records how the project is built, what
was learned about the file format, and what still has to happen in firmware.

Read `TEENSY-PORT-BRIEF.md` 9.15 for why the UI moved to LVGL at all.

---

## Where things are

| | |
|---|---|
| `ui-design/ArgentaUI.spj` | the SquareLine project. **The source of truth for layout.** |
| `ui-design/assets/` | image assets. SquareLine picks up PNGs dropped here. |
| `ui-design/icons/` | the original 40x40 icon artwork, and a contact sheet |
| `ui-design/*.backup`, `.prelabels`, `.preicon` | snapshots taken before each generation pass |
| `src-esp32s3/ui/` | where an export lands. **Empty today.** |
| `src-esp32s3/uiScreens.cpp` | the screens in code. What the panel actually runs right now. |
| `src-esp32s3/uiContract.h` | the widget names both halves agree on |
| `src-esp32s3/uiBind.cpp` | telemetry in, events out, every honesty rule |

**Nothing in the SquareLine project is wired to the firmware yet.** The panel
runs `uiScreens.cpp`. The project can be edited freely without breaking the
machine.

## Project settings (must not drift)

| setting | value | why |
|---|---|---|
| width x height | **480 x 320** | the panel |
| colour depth | **16 bit** | RGB565 |
| LVGL version | **9.6** | MUST equal the pin in `platformio.ini` |
| board | Eclipse with SDL for development on PC | desktop profile, so it does not lock the resolution. Its driver half is discarded - we export UI files only |
| export | **UI files only** -> `src-esp32s3/ui` | never "Create Template Project" |

The LVGL version is the one that bites. An export is generated C calling
LVGL's API directly, so the editor's idea of that API and the library's have
to agree. SquareLine 1.6.3 bundles 8.3.11, 9.1.0, 9.2.2, 9.3, 9.5 and 9.6 -
read its own `lvgl/` folder, which beat both a web search and an AI summary
that were each wrong about this.

## The `.spj` format, as learned by reading it

SquareLine 1.6.3 writes plain JSON and it is far simpler than the bundled
1.5.4 examples suggest. **Widget nodes can be generated by script**, which is
how all six screens were built.

A node is:

```json
{
  "guid": "GUID12345678-72401S1234567",
  "saved_objtypeKey": "LABEL",
  "properties": [ ... ],
  "children": [ ... ]          // optional
}
```

The 1.5.4 examples also carry `cid`, `coid`, `cgid` and `deepid`. **1.6.3 does
not need them** - a minimal project saved by 1.6.3 has only `guid` and
`saved_objtypeKey`. Do not copy those extra fields from the old examples.

Properties are `{nid, strtype, InheritedType, ...value}`. `nid` is a **stable
enumeration**, not a hash - 10 = Name, 20 = Layout, 30 = Layout_type,
90 = Flags, 225 = Scrolling, 230 = Scrollable, 300 = Scrollbar_mode. That is
what makes generation safe.

### Values

| property | encoding |
|---|---|
| `OBJECT/Name` | `strval` - becomes `ui_<Name>` in the export |
| `OBJECT/Position` | `intarray: [x, y]` - **an offset from the Align point** |
| `OBJECT/Size` | `intarray: [w, h]`; `[1,1]` means auto-size |
| `OBJECT/Align` | `strval`: `TOP_LEFT`, `TOP_MID`, `CENTER` ... |
| `LABEL/Text` | `strval` |
| `BAR/Range` | `intarray: [min, max]` |
| `CHART/Number_of_points` | `integer` |
| `CHART/ChartData` | `strval`, a JSON string of series |
| `IMGBUTTON/Image_released` etc. | `strval` - the asset NAME, `"noimage"` when unset |

**Align matters more than it looks.** The default is `CENTER`, which makes
Position an offset from the screen centre. Generation uses `TOP_LEFT` so
coordinates mean the same thing they do in `uiScreens.cpp`.

### Styling

Fonts and colours live inside the widget's `Style_main` property:

```json
{"part": "lv.PART.MAIN",
 "strtype": "LABEL/Style_main",
 "childs": [{"nid": 10000, "strtype": "_style/StyleState", "strval": "DEFAULT",
   "childs": [
     {"nid": 10410, "flags": 4096, "strtype": "_style/Text_Color",
      "intarray": [39,138,222,255], "InheritedType": 7},
     {"nid": 10450, "strtype": "_style/Text_Font",
      "strval": "montserrat_48", "InheritedType": 3}]}]}
```

Colour is `[R, G, B, alpha]`. **Font names can be written straight in** -
`montserrat_48` was set by script and SquareLine showed it correctly on open,
with the enable checkbox ticked. No font needs registering first.

Sizes in use: 12 (captions, tile subs), 14 (labels, status), 16 (titles),
20 (values), 48 (the boiler number). All five are enabled in `lv_conf.h`.

### Images

Drop a PNG into `ui-design/assets/` and restart SquareLine - it scans that
folder, and the file appears in the image dropdowns. **Confirmed working
2026-11-13.** No import dialog needed.

Images are referenced by NAME as a string, so once the asset exists a widget's
image property can also be set by script.

## What is in the project

Six screens. Every name matches `uiContract.h`, because the export produces
`ui_<Name>` and the firmware links against exactly those symbols. **Rename a
widget in the editor and the build breaks at link time** - which is the
failure we want: loud, immediate, and naming the thing that moved.

| screen | holds |
|---|---|
| `ScreenReadout` | boiler chart, big boiler number, target, group, heater bar, weight / flow / pump, status strip, STOP |
| `ScreenHome` | the 3x3 tile grid, nine buttons each with a label and a sub-label, plus the footer |
| `ScreenSetup` | DISPLAY / BREW / WIFI menu, BACK |
| `ScreenDisplay` | brightness down/up, volume down/up, FLIP 180, BACK |
| `ScreenAbout` | machine, both boards, both firmware versions, BACK |
| `ScreenBrew` | setpoint down/up, heater toggle, TARE, ZERO VOL, CLEAR, BACK |
| `ScreenWifi` | status / network / address, SET UP WIFI, FORGET, BACK |

**Seven screens, not six, since 2026-11-13.** `ScreenAbout` was added along
with the VOLUME group on `ScreenDisplay` and the ABOUT tile on `ScreenSetup`,
to match what the firmware gained the same day.

| added | where |
|---|---|
| `CapVolume`, `VolumeDown`, `VolumeUp`, `VolumeValue` | `ScreenDisplay`, rows 130..190 |
| `SetupAboutBtn` | `ScreenSetup`, the free fourth slot at `[250,160]` |
| `ScreenAbout` with `AboutBack`, `AboutHeadVersion`, `AboutControllerVersion` and eight fixed labels | new |

`CapOrientation`, `FlipButton` and `FlipValue` moved DOWN to rows 204..264,
because VOLUME now sits where they were. Same numbers as
`buildDisplayScreen()`.

**Done by script, by deep-copying existing widgets** of the same kind and then
changing name, position and text - so every `nid` property and every style
block came across unchanged rather than being hand-authored. The script
asserts what it wrote by reloading the file: expected widgets at expected
positions, all guids unique, all names unique. **Names must be unique because
the export makes one global per name**; two widgets sharing one would collide
at link time.

**Verified in step, mechanically:** every one of the 73 `ui_*` names declared
in `uiContract.h` now exists in the project, arrays expanded (`ui_HomeTiles[9]`
against `HomeTile0`..`HomeTile8`). Re-run that check after changing either
side.

**One leftover worth knowing about: `ImgButton5` on `ScreenSetup`**, an
IMGBUTTON at `CENTER`, 198x64, with no image set and no counterpart in the
firmware. It looks like something added while trying the editor out. It is
left alone deliberately - it is not firmware's to delete - but if an export
ever lands it will draw an empty button across the middle of the SETUP page,
on top of the tiles. Delete it in the editor, or say so and firmware will drop
it from the file.

### Layout decisions

- **Tile text is `TOP_MID`**: label at `[0,17]`, sub at `[0,40]`. All nine.
- **`HomeTileLbl8` (SETTINGS) is `CENTER`** because that tile has no sub-text.
- **Accent colour is `#278ADE`**, replacing the old cyan.

**Colours are FIRMWARE'S CALL, not John's.** He said so plainly on
2026-11-13: "I don't really care about the accent colors. Pick what seems to
work best." An earlier version of this file recorded the accent as his
decision and told future sessions not to undo it, which overstated it. Pick
what reads well and move on - but keep it CONSISTENT, because the accent is
set in two places that must agree (`kAccent` in `uiScreens.cpp` and
`kTraceColour` in `uiBind.cpp`; see job 3 below).

The same applies more widely: he does not do UI design, and never took it on.
Firmware writes the screens. If a layout is wrong he says what is wrong and
firmware fixes it, so never hand him editor steps as part of the work.

### Icons

`ui-design/icons/` holds 40x40 RGBA PNGs: cup, manual, flush, backflush,
scale, status, settings. The cup is the real artwork from
`assets/coffee-drink.png`; the other six were regenerated from the shapes the
old hand-drawn UI drew with primitives (`drawTileIcon`, now in
`reference/display-lovyangfx/display.cpp`).
These have **real alpha** - the magenta colour-key hack the old RGB565 build
needed is gone.

**Four of them may not be needed.** LVGL's symbol font is built in, so a Label
whose text is a symbol gives a vector glyph with no asset and no flash cost:

| tile | symbol | codepoint |
|---|---|---|
| FLUSH | `LV_SYMBOL_TINT` | U+F043 |
| BACKFLUSH | `LV_SYMBOL_REFRESH` | U+F021 |
| SETTINGS | `LV_SYMBOL_SETTINGS` | U+F013 |
| STATUS | `LV_SYMBOL_LIST` | U+F00B |

Verified against `lvgl/include/lvgl/font/lv_symbol_def.h`. One is placed as a
trial: `HomeTileIcon4` on the FLUSH tile, `TOP_MID` at `[0,56]`, montserrat_20.
**Cup, manual and scale have no built-in equivalent** and need the PNGs.

## WHAT FIRMWARE MUST DO WHEN AN EXPORT LANDS

Nothing is wired yet. Three jobs, none of them John's:

**1. The tile arrays have to go.** `uiContract.h` declares
`ui_HomeTiles[9]` and `ui_HomeTileSubs[9]`. **SquareLine exports individual
globals, not arrays** - it will produce `ui_HomeTile0` .. `ui_HomeTile8` and
`ui_HomeTileSub0` .. `8`, which is how they are named in the project. Change
the contract to declare the nine individually and have `uiBind::begin()`
gather them into a local array.

**2. `uiScreens.cpp` drops out by itself** - `uiContract.h` already does
`#if __has_include("ui/ui.h")`, so the hand-written definitions disappear the
moment an export exists. Remove it from `build_src_filter` at the same time.

**3. The healthy-boiler colour must become `#278ADE`.** DONE 2026-11-13, in
firmware, without waiting for an export - the running UI was still the old
cyan, and the colour is John's recorded pick either way. It is set in TWO
places that must stay in step: `kAccent` in `uiScreens.cpp` for the layout,
and `kTraceColour` in `uiBind.cpp` for the boiler reading and the chart trace.
`uiBind.cpp` sets those AT RUNTIME because they carry meaning, so a value set
anywhere else is overwritten within a second of boot. An export changing the
accent must change `uiBind.cpp` too.

### Colours firmware owns, which the editor cannot

These change with machine state, so styling them in SquareLine has no lasting
effect:

`BoilerValue`, `GroupValue`, `WeightValue`, `FlowValue`, `PumpValue`,
`HeaterPercent`, `StatusLabel`, `HomeFooter`, the heater bar's indicator, and
the BACKFLUSH tile's border and sub-label.

Everything else - captions, titles, backgrounds, button styling, fonts,
positions - is John's.

### And the rule that makes the split work

Generated code (`ui/`) and hand-written code (`uiBind.cpp`) stay separate
because **a re-export overwrites the generated half wholesale**. Every honesty
rule is LOGIC and lives in `uiBind.cpp`: `--.-` rather than a stale value,
chart gaps for unhealthy samples, never "grams" on an uncalibrated scale, the
backflush tile reading `bfa` from telemetry. A layout tool cannot express any
of that, which is exactly why none of it may live anywhere a layout tool might
one day own.
